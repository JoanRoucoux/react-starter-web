# AGENTS.md

Guidance for AI coding agents working in this repository. See the [README](README.md) for the full project overview.

## Project

React 19 application (function components, hooks, React Compiler), built with Vite, routed by React Router, server state in TanStack Query. The app ships no global chrome (header, sidebar, navigation) and renders only its body: it can be embedded in a host shell, or run standalone. No integration mechanism is assumed.

Package manager: **pnpm** (version pinned in the `packageManager` field of package.json). Node 24 (`.nvmrc`).

## Commands

| Command                  | Purpose                                                      |
| ------------------------ | ------------------------------------------------------------ |
| `pnpm install`           | Install deps + regenerate the Orval API client (postinstall) |
| `pnpm start`             | Dev server with API proxy                                    |
| `pnpm run test:coverage` | Unit tests with coverage                                     |
| `pnpm run e2e`           | Playwright end-to-end tests                                  |
| `pnpm run lint`          | ESLint (includes Sheriff module-boundary rules)              |
| `pnpm run format:check`  | Prettier check                                               |
| `pnpm run generate:api`  | Regenerate the API client from `openapi/openapi.yaml`        |

Before considering a change done, run the same pipeline as CI: `format:check`, `lint`, `test:coverage`, `build`, `e2e`.

## Architecture

- `src/app/core/`: global infrastructure (http, i18n, query client, session, logger, validation, 404). `core/api-client/` is **generated by Orval: never edit it**, change `openapi/openapi.yaml` and run `pnpm run generate:api` instead.
- `src/app/features/<feature>/`: one folder per business feature, containing one folder per screen plus `<feature>-routes.tsx`. A screen folder is named after its route segment (`list/`, `detail/`, `create/`) and holds everything that serves only that screen: the page, its hook, its form, its dialogs. A feature with a single screen keeps the page at its root (`features/home/home-page.tsx`). No `pages/`, `hooks/` or `forms/` folders: grouping is by domain, not by technical type.
- **`<feature>-routes.tsx` is the feature's routing entry point**: every feature has one, whatever its number of screens, and it owns the feature's titles (`handle.title`), loaders and lazy pages. Its paths come from the feature's contract (`contract/<feature>-paths.ts`), never from string literals. `app-routes.tsx` imports a feature's routes file and its contract, nothing else: it never reaches for a page directly. A feature is then relocatable (to another app, to another MFE) by moving its folder and changing those imports.
- `src/app/shared/`: reusable presentation/test helpers, imports neither `core` nor `features`.
- Module boundaries are enforced at lint time by Sheriff ([sheriff.config.ts](sheriff.config.ts)): `features` -> `core`/`shared`; `core` -> `shared`; features import each other only through `contract/`; `core` may import contracts; contracts import nothing from the app. Modules are barrel-less: no `index.ts`, import files directly; private files go in an `internal/` subdirectory.
- Import aliases: `@core/*`, `@features/*`, `@shared/*`, `@environments/*`.

## Feature contract

`src/app/features/<feature>/contract/` is a Sheriff module tagged `contract:<feature>`: the only part of a feature that the rest of the app may import. It is named `contract` because "api" already means the backend here (`core/api-client`, `openapi/`, `apiBaseUrl`) and `public/` is the static assets folder.

- A contract holds pure data only: route segments, absolute paths, functions that build links, and their types. Never a component, hook or any `react` import.
- Why: importing another feature's contract must pull only constants into the importer's chunk (lazy loading).
- One file per concern, barrel-less, no `index.ts`. Every feature has `contract/<feature>-paths.ts` with at least its segment (one `<FEATURE>_PATHS` object per feature: `segment`, a `<child>Segment` per child route, then absolute links or link builders): `app-routes.tsx` mounts the feature on it and cannot take it from `<feature>-routes.tsx`, since a static import would make the lazy pages eager.
- Something enters a contract only when a second module needs it. Route parameter names (`:userId`) stay private: the path builder (`USERS_PATHS.detail(id)`) hides them.
- No route path is written as a string outside the feature that owns it: components and navigation read the contract. Specs and e2e keep literal URLs on purpose, since they assert the user-facing URL.

## Adding a page to a feature

1. Create `<feature>/<screen>/` where `<screen>` is the route segment, with `<entity>-<screen>-page.tsx` (+ `.spec.tsx`), component `<Entity><Screen>Page`. **The folder carries the short name, the files carry the full one**: `users/list/user-list-page.tsx`, never `users/user-list-page/user-list-page.tsx`.
2. Name the screen after what it is, not after the CRUD operation, and stick to `list`, `detail`, `create`, `edit`, `form`. One screen handling both creation and update is `form/<entity>-form-page.tsx`, with the mode derived from the presence of the route parameter.
3. If the page has any I/O, build a `use-<entity>-<screen>.ts` hook beside it that calls the generated hooks (`core/api-client/<feature>/<feature>.ts`): see "State and data access" below.
4. Wire the page into `<feature>-routes.tsx` as a lazy route, with a `pageTitle.<key>` title in `handle`.
5. Add its translations to the feature's namespace (`public/i18n/<feature>/<lang>.json`), keyed by screen (`<screen>.*`): see `list.*`, `create.*`, `detail.*` in the users namespace.
6. A form used by a single page is colocated with it (`create/user-create-form.ts`), not in a feature-wide folder.

## Routing

- **Route definitions are eager, pages are lazy.** `app-routes.tsx` and `<feature>-routes.tsx` import no page: each page is a `lazy` route written in the function form, `lazy: async () => ({ Component: (await import('./list/user-list-page')).UserListPage })`. The object form is mutated in place by React Router, which breaks a second router built from the same route objects (tests, HMR).
- **Loaders are the guards.** A feature's loader awaits its access guard, then loads its i18n namespace (`loadNamespace('<feature>')`), see `users-routes.tsx`. A guard sits at the level it protects, on the feature's wrapper route, never in `app-routes.tsx`, or the app knows the feature's access rules and the feature stops being relocatable. A guard `throw redirect(...)`s so the user lands somewhere; tests check the `Location` header.
- Every router builds its root through `createAppRoot` ([app-root-route.ts](src/app/app-root-route.ts)), which sets `HydrateFallback: () => null`: without it React Router logs "No HydrateFallback element provided". Tests use it too (`renderWithProviders`).
- A non-numeric `:userId` becomes `NaN`: the request goes to `/api/users/NaN` and the API's 404 drives the error state.
- `USERS_PATHS.createSegment` (`'new'`) is declared before `':userId'` in `users-routes.tsx` so it is not matched as an identifier.

## State and data access

- **A page never imports a runtime value from `@core/api-client/*`** (ESLint, type imports are allowed). Any I/O lives in a `use-<entity>-<screen>.ts` hook colocated with the screen, and the page interacts with nothing but that hook and local UI state. A screen with local state but no I/O can keep it in the component; a screen with neither (`home-page.tsx`) has no hook at all. This is a layering rule, not a size threshold.
- **A hook serves exactly one thing that opens and closes**: one screen, or one dialog. State that only means something while a dialog is open belongs to that dialog's hook (`delete-dialog/use-user-delete.ts`), never to the screen's.
- **The hook owns the route parameters it depends on**, read with `useParams` (see `use-user-detail.ts`). A page therefore has no route prop to forward.
- **Reads are queries, writes return a result.** Queries are the generated `useGet*` hooks. Commands are `async` functions built on `mutateAsync` that return their outcome (`save()` returns the created user or `undefined`, `remove()` returns a boolean), awaited by the handler that triggered them.
- **A mutation invalidates the queries it makes stale** with the shared `queryClient`: `queryClient.invalidateQueries({ queryKey: getGetUsersQueryKey() })`. Without it the list keeps showing what it fetched on arrival.
- **Navigation stays in the page.** A hook returns a result; the page decides where to go next (`useNavigate` in `user-create-page.tsx`).
- **HTTP goes through the generated client.** Add a hand-written `<feature>-repository.ts` at the feature root only when it earns its place, aggregating several calls into one business operation, mapping DTOs to a view model shared by several pages, or absorbing an API quirk. Never as a pass-through.
- `apiFetch` ([api-fetch.ts](src/app/core/http/api-fetch.ts)) is the Orval mutator. It takes the URL without the `/api` prefix (Orval URLs such as `/users` pass through unchanged), sets `Content-Type: application/json` only when a body is present, rethrows an aborted request untouched and unlogged, and turns any other failure, including a non-JSON 2xx body, into a logged `ApiError`.
- The session query uses `staleTime: Infinity` and `gcTime: Infinity` (`session-query.ts`): the backend is asked once per page load.

## Conventions

- Everything in the repo is written in **English** (code, docs, commit messages).
- No comments, in code and configuration alike. A trap no test can catch goes in Gotchas below.
- Commits follow [Conventional Commits](https://www.conventionalcommits.org), enforced by commitlint. lint-staged formats and lints staged files on commit. A pull request title follows the same rules, since the squash merge turns it into the commit on main.
- Function components and hooks only, named exports, explicit return types (`React.JSX.Element` for components, enforced by ESLint). The React Compiler memoizes: do not add `useMemo`, `useCallback` or `React.memo`.
- Never suffix a module with `-service`: name it after the role it plays (`use-<entity>-<screen>` for a screen hook, `-repository` for adapted data access). Generated code is the exception, it keeps its generator's naming and is never edited.
- Forms use React Hook Form with `zodResolver`: schema and `initial...()` factory in `<entity>-<screen>-form.ts`, colocated with the page, the form instance created in the screen hook. Factories are functions so each page or dialog instance gets its own object. Every `<form>` carries `noValidate`.
- `verbatimModuleSyntax` is enabled: type-only imports must use `import type { X }` or `import { type X }`.
- `console` is forbidden (ESLint) outside `core/logger` and `main.tsx`: use `logger`.
- File names are kebab-case, words separated by dashes, never dots: `page-title.tsx`, `users-routes.tsx`, `app-root-route.ts`. Components and hooks are named after their role (`home-page.tsx`, `use-user-list.ts`, `not-found-page.tsx`). `core/api-client/` is the exception: it is generated by Orval and keeps its own naming.
- Dependabot runs monthly with a 7-day cooldown. Minor and patch updates merge themselves through `.github/workflows/dependabot-auto-merge.yml` once the required checks pass, and majors are reviewed by hand. The README names major versions only, since the exact ones live in the manifests Dependabot bumps.

## i18n (i18next)

- The global `public/i18n/<lang>.json` files only hold keys needed synchronously before any feature namespace loads: `pageTitle.*` (used by `PageTitle` on navigation) and the 404 page. They are loaded by `initI18n()` before the app renders: keep them minimal.
- Each feature has a lazy namespace in `public/i18n/<feature>/<lang>.json`, loaded by `loadNamespace('<feature>')` in the feature's route loader. Pages call `useTranslation('<feature>')` and read keys without the prefix (`t('list.title')`).
- English is the default language, a first visit follows the browser language when it is supported, and a persisted choice (the `lang` cookie) always wins (`core/i18n/i18n.ts`).
- Every key must exist in both `en` and `fr`.

## Testing

- Component tests use React Testing Library through `renderWithProviders` (`shared/testing`): query by role or label, not by CSS selectors. Screen hooks use `renderHook`. jest-dom matchers and the `<dialog>` shim are set up in `src/test-setup.ts`.
- HTTP is mocked with MSW 3 (`shared/testing/msw-server.ts`), started with `onUnhandledFrame: 'error'` (not `onUnhandledRequest`): a route test that renders `/users` must register a handler.
- Test i18n (`shared/testing/test-i18n.ts`) has no resources: a missing key renders as the key (default namespace) or `ns:key`.
- jsdom implements no `<dialog>` behavior: [src/test-setup.ts](src/test-setup.ts) shims `showModal`/`close` so specs can drive the markup, and the semantics that matter, initial focus on the safe action, Esc, focus returned to the trigger, are asserted in the Playwright suite instead.
- `coverage.include` in [vite.config.ts](vite.config.ts) makes every source file count, including those no spec imports. `coverage.exclude` holds the generated client and the pure wiring (bootstrap, `*-routes.tsx`, environments, test helpers); anything with behavior gets a spec. The thresholds (85/80/70/85) are intentionally low so downstream users of the starter are not blocked: do not raise them.
- `data-testid` attributes in markup are used by the Playwright e2e page objects: keep them even where unit tests query by role.

## Gotchas

- TypeScript stays on 6.x (pinned to `6.0.3`, Dependabot ignores `>=7`): `typescript-eslint` does not support TypeScript 7 yet. Do not bump until it does.
- Orval writes a root `index.ts` into `core/api-client/` that turns it into a barrel Sheriff refuses deep imports from; the `afterAllFilesWrite` hook in `orval.config.ts` deletes it.
- `pnpm-workspace.yaml` sets `saveExact: true`: `pnpm add` records exact versions, keep it that way. `allowBuilds` lists the dependencies whose install scripts may run (here `esbuild: false`, denied on purpose: Vite 8 does not need it). Dependency versions must respect pnpm's minimum release age (one day by default): pin the newest version older than that, and do not exempt a fresh release.
- The Sheriff config uses `import type { SheriffConfig }`: `verbatimModuleSyntax` rejects a value import of a type.
- The `@environments/environment` alias comes before `@environments` in the alias array of `vite.config.ts`: Vite takes the first match, and the generic one would swallow the specific one.
- The React Compiler runs through `@rolldown/plugin-babel` in dev and build, and is skipped when `process.env['VITEST']` is set, so coverage measures the source as written.
- Vitest `include` is limited to `src/**/*.spec.{ts,tsx}`, or it would pick up the Playwright specs. Vite `server.watch.ignored` keeps `playwright-report`, `test-results` and `coverage` out of the watcher. The suspected cause, unconfirmed: a dev server reload when Playwright writes its report makes a cold-start e2e run flaky.
- `eslint-plugin-jsx-a11y` declares a peer of ESLint below 10, so pnpm prints a peer warning on install; lint works on ESLint 10.
- ESLint turns the hook rules off in `e2e/fixtures`: Playwright fixtures take a `use` callback that looks like a hook.
- `prettier --write .` rewrites Markdown too: run `pnpm run format` knowingly.
- GitHub Actions in `.github/workflows/ci.yml` are pinned by commit SHA with the version in a trailing comment (Dependabot keeps them updated): when adding one, pin it the same way.
- nginx sets every header at server level only. An `add_header` inside a `location` silently drops all server-level headers (CSP included) for that location; per-path `Cache-Control` goes through `map $uri $cache_control`. Hashed filenames under `/assets/` and `/media/` are cached a year, everything else revalidates. That one header has no `always`: with it, a 404 for a stale hashed name would be cached a year too.
- A path whose last segment contains a dot is treated as a file (`location ~ \.[A-Za-z0-9]+$`) and answers 404 instead of `index.html`: a route parameter that may hold a dot (an email, a version) needs another shape.
- The CSP is `script-src 'self'` with `require-trusted-types-for 'script'; trusted-types 'none'`, and `frame-ancestors 'none'` forbids embedding the app in an iframe. A new inline script needs a hash or must become a file.
- Zod 4 probes `Function('')`, which the Trusted Types CSP blocks. `core/validation/zod.ts` sets `jitless: true`, and ESLint forbids importing `zod` anywhere else (exact specifier only): import `z` from `@core/validation/zod`. Do not import it from `main.tsx`, so Zod stays in the lazy create-page chunk. The violation shows only in the Docker image, not in dev or Vitest: after touching the CSP or adding a dependency, run a browser pass against the image.
- `zodResolver` passes the Zod-parsed output to `handleSubmit`, so names and email are trimmed before the POST. `z.email()` is stricter than the browser's email check (`a@b` is rejected).
- The HEALTHCHECK targets `127.0.0.1`, not `localhost`: `localhost` resolves to `::1` in the alpine image. The `docker` job of `ci.yml` waits for the container to be healthy.
- The required status check `ci` is the gate job at the end of `ci.yml`, not a build job: a new CI job must be added to its `needs`, or its failure will not block a merge. It runs `if: always()`, never `!cancelled()`: a cancelled run must turn the gate red.
- Dependabot never bumps the Node major in the Dockerfile (it ignores semver-major for the `node` image): the Node major lives in `.nvmrc`, `engines` in package.json, the Dockerfile and the CI `node-version`, changed together by hand.
- `apiFetch` only logs. Showing a failure is the job of the screen that asked (each hook exposes `isError` or `error`), because a toaster raised from the fetch layer would duplicate or replace that message.
- `initI18n()` is awaited before the first render in `main.tsx`: without it the first paint shows keys instead of text.
- The detected language can be regional (`fr-FR`): `<html lang>` and `useActiveLang` reduce it with `Intl.Locale(...).language`.
- Loading a namespace also fetches the fallback language file: an MSW spec that loads real i18n must handle both `en` and `fr`.
- `close()` on a `<dialog>` restores focus to the element that opened it. `UserDeleteDialog` calls `close()` before its callbacks and again on unmount (StrictMode runs the effect twice), and after a deletion the page moves focus to the list heading, because the row that held it is about to disappear.
- A live region only announces changes to a region that was already in the DOM: the status paragraph of the user list renders even when empty.
- `showModal()` focuses the first focusable element of the dialog: keep the destructive action second (`user-delete-dialog.tsx`).
- A merge made with `GITHUB_TOKEN` triggers no `push` workflow, which is why `dependabot-auto-merge.yml` uses the `DEPENDABOT_MERGE_TOKEN` secret when it exists.
- Generator: `.generator/templates/src/app/app.spec.tsx` mirrors `src/app/app.spec.tsx` and must be kept in sync. The `e2e` folder is removed whole and restored by templates: an e2e helper used by the generated spec needs a template too. Manifest `replace` entries match exact text (for example `HOME_PATHS` in `not-found-page.tsx`): editing those lines breaks the generator check. See [.generator/README.md](.generator/README.md).
